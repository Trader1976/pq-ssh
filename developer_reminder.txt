We are continuing development of pq-ssh, a Qt/C++ SSH client with practical post-quantum support experiments.

Key facts:
- Language: C++17 + Qt (Widgets)
- Interactive terminal path: external OpenSSH client (`ssh`) launched inside QTermWidget
- Programmatic SSH path: libssh
- Current bundled libssh version for AppImage builds: 0.12.0
- Terminal widget: QTermWidget with CPUNK-specific integration/fixes
- Project has an `ARCHITECTURE.md` that describes the structure
- We already heavily commented these files:
  - `SshClient.{h,cpp}`
  - `ProfileStore.{h,cpp}`
  - `ProfilesEditorDialog.{h,cpp}`
  - `ThemeInstaller.cpp`
  - `TerminalView.{h,cpp}`
  - `SshShellWorker.{h,cpp}`
  - `KeyGeneratorDialog.{h,cpp}`
  - `DilithiumKeyCrypto.{h,cpp}` if still present in this branch/repo state
- Important architecture split:
  - OpenSSH path is used for the interactive shell/terminal
  - libssh is used for SFTP, remote file operations, and small exec helpers
- Current state:
  - App version has been bumped from `1.0-beta` to `1.0`
  - Linux AppImage release now bundles private libssh 0.12.0
  - AppImage payload was verified to use bundled libssh, not system libssh
  - SFTP/libssh KEX reporting was fixed so it no longer falsely says libssh is classical-only
  - libssh SFTP path now prefers PQ-capable KEX in this order:
    - `mlkem768x25519-sha256`
    - `mlkem768nistp256-sha256`
    - `sntrup761x25519-sha512@openssh.com`
    - `sntrup761x25519-sha512`
    - `curve25519-sha256`
  - Interactive terminal/OpenSSH path still uses hybrid PQ via `sntrup761x25519-sha512@openssh.com`
  - Dilithium / ML-DSA keys are still NOT used for SSH authentication
  - SSH authentication remains OpenSSH-compatible (currently Ed25519/OpenSSH key flow)
  - Key installation uploads OpenSSH-style public keys into `authorized_keys`
  - DNA / mnemonic identity logic now DOES exist in the project:
    - mnemonic-based deterministic identity derivation
    - PQ identity branch / fingerprint derivation
    - deterministic SSH identity derivation
  - Clipboard bug fix was recently completed
  - Release packaging and GitHub release for `v1.0` were completed
